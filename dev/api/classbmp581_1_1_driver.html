Verify chip id (0x50 / 0x51) and NVM readiness.

On SPI (and for an adapter that does not declare kInterface) the first access is the dummy read that switches the chip from I2C to SPI (datasheet section 5.1); its data is discarded.

◆ SoftReset()

template<typename BusT >
DriverResult< void > bmp581::Driver< BusT >::SoftReset ( )
inlinenoexcept

Soft reset: CMD = 0xB6, wait t_soft_res (2 ms), reselect SPI, verify.

  • Over I2C the chip does not acknowledge the reset command (datasheet section 7.36), so a failed status from that one write is expected and not an error. With kInterface == Interface::Spi it is reported as Bus.
  • The reset returns the interface to I2C (section 5.1, Table 16); on SPI (or an undeclared interface) one dummy read selects SPI again.
  • The reset is then verified as section 4.3.9 recommends: CHIP_ID not 0 (InvalidChipId), STATUS nvm_rdy = 1 and nvm_err = 0 (NvmNotReady, NvmCommandError), INT_STATUS por = 1 (PorSoftReset). Every read after the reset command reports its own bus error as Bus.
