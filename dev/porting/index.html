Porting¶

Run the driver on a new MCU by writing one class: the register transport, over I2C or SPI.

The driver never calls your SDK directly. It calls four methods on a class you derive from bmp581::BusInterface<Self> (in inc/bmp581_bus_interface.hpp). The base class uses CRTP: the calls are resolved at compile time, so there are no virtual functions, no vtable and nothing to allocate.

Figure description and sources

From top to bottom. Your application talks to one bmp581::Driver object, whose public calls are listed from inc/bmp581_driver.hpp. Each call becomes register reads and writes in the order the datasheet requires (the standby hop, IIR writes in standby, POR and NVM checks). The register transport (BusInterface in inc/bmp581_bus_interface.hpp) is a CRTP base with four methods. The platform port is the only code you write: a class that implements them over I2C or SPI. Below it is the sensor.

Drawn from: inc/bmp581_driver.hpp Driver public members; inc/bmp581_bus_interface.hpp BusInterface; figure module docs/diagrams/figures/driver-layers.py.

What you implement¶

Method Contract
bool WriteRegs(uint8_t reg, const uint8_t* data, std::size_t len) Write len bytes to reg, reg + 1, ... Return false on a bus error. The driver writes at most 2 bytes at a time
bool ReadRegs(uint8_t reg, uint8_t* out, std::size_t len) Read len bytes from reg onwards into out. The driver reads at most 6 bytes at a time
void DelayUs(uint32_t us) Block for at least us microseconds. The driver asks for 800 µs to 5 ms
bool EnsureInitialized() Return true when the bus is ready. Init() calls it first and fails with NotInitialized otherwise

All four must be noexcept-compatible: the driver's calls are noexcept.

I2C port¶

my_i2c.hpp
class MyI2c : public bmp581::BusInterface<MyI2c> {
public:
  // 7-bit address: 0x46 with SDO low, 0x47 with SDO high.
  explicit MyI2c(uint8_t address = bmp581::addr::kSecondary) noexcept : address_(address) {}

  // One transaction: [reg, data...]. The chip increments the register address after each byte.
  bool WriteRegs(uint8_t reg, const uint8_t* data, std::size_t len) noexcept {
    uint8_t frame[16];
    if (len + 1 > sizeof(frame)) {
      return false;
    }
    frame[0] = reg;
    std::memcpy(frame + 1, data, len);
    const bool acked = platform_i2c_write(address_, frame, len + 1);
    // The BMP581 does not acknowledge a soft-reset command over I2C: count that write as sent.
    const bool soft_reset = reg == bmp581::reg::kCmd && len == 1 && data[0] == bmp581::cmd::kSoftReset;
    return acked || soft_reset;
  }

  // Write the register address, repeated START, read len bytes (auto-increment).
  bool ReadRegs(uint8_t reg, uint8_t* out, std::size_t len) noexcept {
    return platform_i2c_write_read(address_, &reg, 1, out, len);
  }

  void DelayUs(uint32_t us) noexcept { platform_delay_us(us); }

  // Called before every Init(); bring the bus up here if your SDK needs it.
  bool EnsureInitialized() noexcept { return true; }

private:
  uint8_t address_;
};

Rules the transfer must follow:

  • One transaction per call. A write is START, address, register, data, STOP. A read is START, address, register, repeated START (or STOP and START), address, data, STOP.
  • Count a soft reset as sent. The chip does not acknowledge the data byte when CMD (0x7E) is written with 0xB6 (datasheet section 7.36). If your SDK reports the missing acknowledge as an error and the port passes it on, SoftReset() returns Bus and Init() cannot recover a part whose NVM boot did not finish.
  • Do not let SDO float. It sets the address bit; floating, the address is undefined.

SPI port¶

my_spi.hpp
class MySpi : public bmp581::BusInterface<MySpi> {
public:
  // SPI writes do not auto-increment: send one (address, data) pair per byte, bit 7 clear.
  bool WriteRegs(uint8_t reg, const uint8_t* data, std::size_t len) noexcept {
    uint8_t tx[16];
    uint8_t rx[16];
    if (2 * len > sizeof(tx)) {
      return false;
    }
    for (std::size_t i = 0; i < len; ++i) {
      tx[2 * i] = static_cast<uint8_t>((reg + i) & 0x7FU);
      tx[2 * i + 1] = data[i];
    }
    if (!platform_spi_transfer(tx, rx, 2 * len)) {
      return false;
    }
    if (reg == bmp581::reg::kCmd && data[0] == bmp581::cmd::kSoftReset) {
      // A soft reset returns the interface to I2C mode; one dummy read selects SPI again.
      platform_delay_us(bmp581::timing::kSoftResetUs);
      return DummyRead();
    }
    return true;
  }

  // Reads: address with bit 7 set, then the data bytes (auto-increment); no dummy byte.
  bool ReadRegs(uint8_t reg, uint8_t* out, std::size_t len) noexcept {
    uint8_t tx[16] = {};
    uint8_t rx[16] = {};
    if (len + 1 > sizeof(tx)) {
      return false;
    }
    tx[0] = static_cast<uint8_t>(reg | 0x80U);
    if (!platform_spi_transfer(tx, rx, len + 1)) {
      return false;
    }
    for (std::size_t i = 0; i < len; ++i) {
      out[i] = rx[i + 1];
    }
    return true;
  }

  void DelayUs(uint32_t us) noexcept { platform_delay_us(us); }

  // The chip powers up in I2C mode. The first SPI read switches it to SPI; its data is invalid.
  bool EnsureInitialized() noexcept {
    if (!spi_selected_) {
      spi_selected_ = DummyRead();
    }
    return spi_selected_;
  }

private:
  bool DummyRead() noexcept {
    uint8_t tx[2] = {static_cast<uint8_t>(bmp581::reg::kChipId | 0x80U), 0};
    uint8_t rx[2] = {};
    return platform_spi_transfer(tx, rx, sizeof(tx));
  }

  bool spi_selected_ = false;
};

Rules the transfer must follow:

  • SPI mode 0 or 3, MSB first, up to 12 MHz (7 MHz with VDDIO under 1.62 V).
  • Writes do not auto-increment. Send an address byte (bit 7 clear) before every data byte, as the datasheet's burst-write figure shows. The driver writes two consecutive registers in SetOsrOdr() and SetIir().
  • Reads set bit 7 of the address and return data from the next byte on, with auto-increment.
  • Select SPI with a dummy read after power-up and after every soft reset: both return the chip to I2C mode, and the read that switches it returns invalid data.
Call from the driver Bytes on the bus
WriteRegs(0x36, {a, b}, 2) [0x47 W] 0x36 a b
ReadRegs(0x1D, out, 6) [0x47 W] 0x1D [0x47 R] t0 t1 t2 p0 p1 p2
Call from the driver Bytes on the bus (CSB low for each line)
WriteRegs(0x36, {a, b}, 2) 0x36 a 0x37 b
ReadRegs(0x1D, out, 6) 0x9D then six bytes clocked in: t0 t1 t2 p0 p1 p2

Reference implementation¶

The ESP32 examples use hf_bmp581_esp_i2c.hpp: Bmp581EspIdfI2c<port, sda, scl, address, speed>, an I2C port on the legacy ESP-IDF driver/i2c.h API with FreeRTOS delays. Start from it for any ESP-IDF target, and add the soft-reset exception above.

Check your port¶

  1. Build it: both ports on this page are compiled by the host CI from tests/docs/, with the driver instantiated over them.
  2. Call Init() and print ChipId(): 0x50 proves register reads end to end.
  3. Call SoftReset(): ok() proves the CMD write, the reset wait and (on SPI) the dummy read.
  4. Call Configure(), then GetOsrOdr(): reading back what you wrote proves two-byte writes.
  5. Read a few samples: about 101 kPa at sea level, falling by about 12 Pa per metre of height.

Threads¶

The driver is not thread-safe. Give each sensor one owner task, or guard every call on a driver object (and its port) with one mutex. Several sensors on separate ports, or at both addresses of one I2C bus, can run in parallel as long as the bus driver serialises transactions.
